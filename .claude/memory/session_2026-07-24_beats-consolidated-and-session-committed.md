## Beats consolidation (the substantive part)
`sidecoach/.claude/memory/` was not a few stray teammate beats - it was **37 files of real history back to 2026-05-21**, a second corpus running alongside the canonical project-root record.

**Why it mattered, concretely:** a teammate working in `sidecoach/` reported that two of my beat files "do not exist" and proposed working around their absence. It was reading the nested directory while the beats sat in the root one. A split record does not merely duplicate - it produces confidently wrong reports about what has and has not been recorded, which is the exact opposite of what a continuity layer is for.

**How:** `git mv` for the 33 tracked files so history follows them (git confirmed 33 renames), plain `mv` for 4 untracked. Filenames were unique - only `MEMORY.md` collided - so every index link still resolves. The 14 nested index lines were appended to the root index, then relocated to `MEMORY-archive.md` by the compaction hook (its designed behaviour; verified all 14 are still recorded, nothing lost).

**Verification that actually caught something:** a link-resolution sweep over the merged index found 1 dangling reference - `session_2026-05-23_phase2_task8.md` does not exist, the file is `phase2_task8_9.md`. That was a PRE-EXISTING error in the nested index that my merge imported. Fixed. Re-swept: 45 links, 0 dangling, 1057 beats now in one place.

**Tombstone, not deletion.** The bash-guard correctly BLOCKED `git rm` against `.claude/memory` ("destroys session beats - move to trash or rename instead"). Rather than fight a guard that was doing its job, the old path now holds a pointer explaining the migration and telling anything landing in `sidecoach/` to write to the root. That is a better outcome than deletion: it prevents the split from being recreated.

**Flagged, not fixed:** the root corpus has **337 beat files not referenced from either index**. Pre-existing, not caused by this migration, but a real gap in the record's navigability.
