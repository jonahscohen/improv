Jonah's team is wary of a TUI-within-CLI install and wants a more "visually secure" install path that keeps the a-la-carte component ideology, fitting Claude Desktop rather than raw CLI. Ruled out via AskUserQuestion forks; chose to BUILD a real browser GUI installer (over the already-existing flag paths and the Desktop-pick option).

**Decisions locked (brainstorming):**
- Execute model: one-click RUN via a tiny local server (not emit-command-only). Security preserved by construction.
- List source: `install.sh --manifest` emits JSON (from browser-tree.json + TITLES/DESCS/FILES + state); server serves it. Single source of truth, no drift.
- Launch: new `install.sh --gui`; `ampersand --gui` free (ampersand forwards flags).

**Architecture:** 3 layers, GUI is a thin front-end. Browser page <-> localhost server <-> install.sh core (browser-tree.json). TUI, CLI flags, GUI = three doors to ONE apply engine.

**Four build units:**
1. `install.sh --manifest` - JSON emitter, mirrors the existing `--help` python3 tree walk. No side effects.
2. `install.sh --gui` - starts server, `open`s browser.
3. Local server - python3 stdlib only (matches serve.py), 127.0.0.1 + ephemeral port + one-time nonce + Origin/Host check; endpoints GET / , GET /manifest, POST /dry-run, POST /apply (streamed log), POST /shutdown; keys allowlisted + `^[a-z0-9-]+$` + argv-list never shell=True.
4. The page - ADAPT the existing prototype `docs/superpowers/specs/2026-07-16-installer-bucket-browser-prototype.html` (already a complete client-side bucket browser; it is a MOCK - hardcoded tree, faked seed() state, no-op apply). Change exactly 3 things: hardcoded T -> fetch('/manifest'); seed() -> manifest state; applyPending() no-op -> POST /apply + live-log panel.

**Grounding verified @84432079:** browser-tree.json = tree source of truth; browser-lib.sh = accessors (item_state/counts); install.sh KEYS/TITLES/DESCS/FILES arrays; `--help` already walks the tree via python3; per-component `deactivate_*` functions exist; headless install contract = `--only KEYS` + `_AMPERSAND_HOOK_ON/OFF`; `component_browser()` is the interactive apply engine the GUI shares.

**Scope v1:** manifest + gui + server + adapted page + install AND toggle-off (deactivate_* via shared engine; add a small headless off entry only if `--only` cannot express whole-component off). **Deferred:** update/re-sync banner (prototype fakes it), --personal bucket in GUI, bootstrap-level `--gui`, web-app restyle (keep terminal-window aesthetic).
