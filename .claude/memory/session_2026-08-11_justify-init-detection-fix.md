Andrew's review of the improv repo (from his /Users/spare4 checkout) found a second Justify CLI bug, in the INSTALLER this time (the uninstall bug he also reported was already fixed this session - his report predated it). Jonah chose "fix the installer detection".

**Four defects confirmed in the source and fixed (justify/cli/init.sh):**
1. Detection set `$STACK`, but the WIRING branched on its OWN independent `[ -f vite.config ]` / `[ -f next.config ]` checks, so the two could disagree. Run from a theme dir with a vite.config but no wp-config, it detected "vite", wired nothing, and STILL reported success. FIX: wiring is now a single `case "$STACK"`, so detection and wiring can never diverge.
2. The `.justify` marker + "Justify activated" were written UNCONDITIONALLY (before wiring). FIX: a `WIRED` flag flips to 1 only when a target file is actually wired (or already is); the marker is written and success printed ONLY when `WIRED=1`; otherwise it prints an honest "NOT wired (detected X, no target found)" + a manual snippet and `exit 1`, and writes no marker.
3. The WordPress theme was chosen by glob order (first non-twenty), so it landed on `event-microsite` instead of `event-microsite-mcaa2027`. FIX: honest selection - `JUSTIFY_THEME` override wins, else WP-CLI's active theme (`wp option get stylesheet`), else the single non-twenty theme with a functions.php, else REFUSE to guess: list the candidates and stop (exit 1).
4. Minor: the WP_DEBUG edit cleaned up `wp-config.bak` but sed writes `wp-config.php.bak`, leaking a .bak. FIX: correct filename.
Also added a NOTE when a vite/generic detection happens inside what is really a WP theme dir (has functions.php or a `Theme Name:` style.css): tells the user to run from the site root.

**Kept intact:** the generated WordPress block is byte-identical (with the `// justify:dev:end` marker), so it still round-trips through the fixed remove.sh. bash 3.2 compatible (no arrays; macOS ships bash 3.2.57).

**Verified (26/26 per-stack fixture on bash 3.2.57):** vite/next/generic with a target -> wired + marker; without a target -> exit 1, no marker, honest warning; WP single theme -> right theme; WP multiple -> refuse + list, no marker, exit 1; JUSTIFY_THEME override -> named theme only; twenty* skipped; drupal wired; theme-dir NOTE shown; idempotent re-run no double-wire; init->remove round-trip clean.

**Codex review -> WIRED-semantics rewrite.** First review (204.8s) found the core flaw: `WIRED=1` was set after a sed/append that can EXIT 0 WITHOUT inserting anything - HIGH cases: index.html with no lowercase `</head>`, a Next layout with no `</body>`, and (HIGH) a spaced `define( 'WP_DEBUG', false )` that the old strict sed no-op'd, so the WP_DEBUG-guarded loader was inert while init reported success. Plus MEDs: Drupal library-added-without-template-attach counted as success; broad substring "already wired" checks; unvalidated `JUSTIFY_THEME`. Refactored so WIRED is set ONLY by re-grepping the file for the loader AFTER editing (verify, not "sed ran"), split off an EDITED flag so partial edits (Drupal library w/o template) still get a marker for cleanup, made WP_DEBUG space-tolerant + a verify-and-warn NOTE when it stays inert, keyed WP idempotency on the `// justify:dev` marker (round-trip) not the handle, validated `JUSTIFY_THEME` as a plain slug (rejects `../`), and made "already wired" checks specific (`src="...justify-core`).

**Re-verified (27/27, bash 3.2):** 19 on the findings - vite/next no-op sed -> honest fail + no marker; spaced WP_DEBUG false -> flipped true; no false inert warning when true; Drupal library-without-template -> marker-for-cleanup + exit 1 + honest note + round-trips through remove; JUSTIFY_THEME `../` traversal rejected; WP round-trip clean; idempotent - plus 8 regression (single/multi/twenty*-skip theme selection, generic-no-html, theme-dir note).

**SECOND init review folded (138s):** more honesty bugs, all fixed: Drupal marked wired on ANY `justify-dev` text in a template (now requires the library DEFINED in libraries.yml AND this theme's EXACT `attach_library('THEME/justify-dev')` present, and never adds a dangling attach when no libraries.yml exists); the WordPress arm flipped WP_DEBUG BEFORE choosing the theme, so a multi-theme refusal left a stray edit (theme selection now runs FIRST, wp-config is only touched once a real theme+functions.php is in hand); Next could orphan an unused import when there was no `</body>` (now guards on `</body>` before adding anything); WP_DEBUG "Added" was printed even when the anchor-insert no-op'd (now appends on the no-anchor path and reports WP_DEBUG's ACTUAL verified state, with a quote-anchored regex that excludes WP_DEBUG_LOG); WP idempotency keys on the anchored `^// justify:dev$` line; JUSTIFY_THEME rejects `..` and any non-slug char.

**Re-verified after the second fold (16/16, bash 3.2):** Drupal decoy-only (foreign attach, no libraries.yml) -> template untouched, no marker, honest warning; Drupal full -> wired; Drupal library-no-template -> marker+round-trip; WP multi-theme refuse leaves WP_DEBUG untouched + no marker; Next no-</body> -> no orphan import; WP_DEBUG no-anchor -> actually appended + reported enabled; JUSTIFY_THEME `..` rejected; plus the full happy-path/round-trip/theme-selection sweep.

**THIRD/convergence init review folded (141.5s):** narrower correctness/robustness bugs, all fixed: Drupal `LIB_OK` matched ANY `justify-dev` text (a `# TODO justify-dev` comment or `some-justify-dev-helper:` key) - now an anchored top-level key check `^justify-dev:`; WordPress `WIRED=1` even when the WP_DEBUG-gated block is inert because WP_DEBUG is off (e.g. a double-quoted or uppercase-FALSE define the flip could not fix) - WIRED now requires the block present AND WP_DEBUG verified true, else an honest inert NOTE + exit 1 (block still added + marker for removal); the WP_DEBUG flip is now quote-agnostic (single/double) with a case-consistent grep+sed (uppercase FALSE it cannot flip -> honest inert, not a silent mismatch); `$JUSTIFY_URL` is escaped for sed replacements (`&`/`\`/`|`) so a URL with query params no longer corrupts the inserted tag; and the HTML/Next verify + idempotency now key on the EXACT `$JUSTIFY_URL` (not the `justify-core` substring), so a custom loader URL both verifies correctly and gets a removal marker (no orphan). Re-verified 27 more checks incl. URL-with-&, custom URL, double/single/uppercase WP_DEBUG forms, decoy YAML, plus the full happy-path/round-trip sweep.

**FOURTH review folded, then STOPPED the loop (decision).** The 4th review (240.5s) found two more, both from the inherent limit of matching PHP with grep: a COMMENTED `// define('WP_DEBUG', true)` read as enabled, and a stale `// justify:dev` marker with no enqueue read as a present loader. Folded: WP_DEBUG detection (flip grep, flip sed, and the verify) now carries a `^[^/#*]*` non-comment anchor so a commented define never counts (grep+sed anchored identically); the loader check keys on the actual `wp_enqueue_script('justify-dev'` CALL, not the marker line, and re-adds a working block if only a stale marker is present; and EDITED is no longer set by WP_DEBUG-only changes (remove.sh does not revert WP_DEBUG, so it needs no breadcrumb). Verified 13 more (commented true/false, stale marker, inline-comment false, plus regression).

**DECISION - stop iterating (Jonah to override if he wants more):** four cross-model reviews, ~90 fixture checks, every finding folded. Reviews 2-4 each found progressively narrower cases in ONE class: grep/sed cannot fully parse PHP config semantics (a define behind a conditional, a heredoc, a multi-line statement can still be misread). The load-bearing invariants now HOLD and are the right floor: init never claims false success (WIRED requires the loader verifiably present AND loadable), never corrupts a file (URL escaped, sed anchored), and never orphans/false-markers. Residual failures degrade to HONEST "not activated / inert" messages, not data loss. Continuing is infinite polish against an undecidable target; the core ask (honest detection + right theme) was solid several iterations ago.
