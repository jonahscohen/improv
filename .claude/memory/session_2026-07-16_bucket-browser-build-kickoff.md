**COORDINATOR ERROR (recorded per the self-analysis rule):** I asserted SIGPIPE 141 fires "whenever there are MORE than 10 incoming commits." WRONG. Measured: 15 commits -> rc 0; 65 -> rc 0; 165 (large subjects) -> rc 141. SIGPIPE requires `git log` to still be WRITING when `head` exits, so a backlog fitting the pipe buffer completes cleanly: >10 lines is NECESSARY but the remaining BYTES decide whether it faults. Why I got it wrong: I reasoned from the mechanism (head exits early -> writer gets SIGPIPE) without accounting for the pipe buffer absorbing small backlogs, then stated it as a measured fact. The ruling survived (a size-dependent failure is WORSE - invisible in small tests, fires only for far-behind repos, exactly the installs that most need the row), but the implementer had to correct my number in install.sh's comment, its beat, and the test. Lesson: state mechanism-derived predictions as hypotheses to measure, not as facts to copy into comments.
