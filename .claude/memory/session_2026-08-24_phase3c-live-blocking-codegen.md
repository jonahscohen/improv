**C1 - the ledger-gated codegen (the security boundary).**
- `sidecoach/scripts/generate-enforced-rules.ts` (thin wrapper, mirror generate-counter-rules) + `sidecoach/src/validators/enforced-rules-generation.ts` (pure gate, rootDir ./src so the test imports it). Reads data/enforced-rules/*.json. Empty tier -> emits an empty module (no audit, no secret side effect - the common case works on any machine). Non-empty -> (1) runs the enforce-CLI `audit` (the HMAC ledger chain + head anchor + content-digest match; NOT reimplemented - delegated to the tested enforce CLI); a NON-ZERO audit -> exit 3 -> build breaks. (2) Precision gate per rule: the LEDGERED precision >= threshold + a non-empty precision-digest, AND a matching precision RECORD (pass, precisionDigest === the ledger's SIGNED precision-digest, buildStamp === CURRENT interpreter build). Any failure -> exit 4 -> build breaks. (3) Emits `src/validators/enforced-rules.generated.ts` with the certified patternSpec ProductRuleDefinitions at severity major, tagged mined-taste, exampleCorpus DROPPED. `--check` catches a drifted committed file (exit 1), wired into `npm run build` FIRST (before generate-validators reads RULES).
  Why: the codegen is the crossing point, so it must fail-closed; a tampered/unledgered/under-precision/stale enforced rule can NEVER compile live. Reused the enforce audit for the crypto (no HMAC re-impl -> no drift).
  BuildStamp is now SOURCE-ONLY (pattern-spec.ts + pattern-interpreter.ts) in BOTH the harness and the codegen, so the codegen (runs before tsc emits dist) computes the same stamp with no build-order dependency on dist.
  verify: `src/__tests__/enforced-rules-generation.test.ts` 34/34 (valid certifies at major; every tamper class rejected). `claude/hooks/test-enforced-codegen.sh` PART A: real enforce -> codegen certifies + the patternSpec FIRES via the interpreter; tampered ledger -> exit 3; stale/absent precision -> exit 4; --check drift -> exit 1.

**CAN AN AGENT MAKE A RULE LIVE-BLOCKING WITHOUT THE USER'S TYPED ENFORCE SIGN-OFF?** No. To be live, a rule must be in ENFORCED_RULES (generated). The codegen emits it ONLY after the enforce-CLI audit verifies an HMAC-signed ledger entry (secret is guard-fenced from agents; the entry is minted only by the user's typed enforce-confirm) + a precision proof. An agent forging a data/enforced-rules/*.json without a valid ledger entry -> audit FAILS -> build breaks (fail-closed, not a silent live rule). An agent hand-editing the generated .ts -> generate-enforced-rules --check DRIFT -> build breaks; and the C4 invariant test fails loud. The residual is the same ACCEPTED same-uid secret-forge limit as promote/enforce; not newly introduced. NOTE (flagged to lead): the generated file + data/enforced-rules + ledger are NOT guard-fenced from agent Writes - an agent CAN dirty them, but every such tamper BREAKS THE BUILD rather than producing a live rule (fail-closed). If defense-in-depth is wanted, fence the generated file + enforced tier from agent Writes (they are never hand-edited).

- HIGH #2 (content-binding skippable): the audit + the derive only checked content_digest WHEN PRESENT, so an HMAC-valid but content_digest-less row escaped content-binding. **CODEX ROUND 3 (LAST fold round - after this we are at the fundamental same-uid floor), 2026-08-24:**
- CAVEAT B FOLD (precision-cache tamper-resistance): the codegen compared the cache's precisionDigest STRING to the ledger but did not RECOMPUTE it from the cache fields, so a same-uid cache rewrite could CLAIM a production floor while its signed ledger digest was for a weakened floor. FIX: the codegen wrapper now RE-COMPUTES the precision digest from the cache's OWN stable fields (ruleId, buildStamp, specHash, threshold, the 3 floor fields, tp/fp/fn/tn, fires, precision, floorsMet/thresholdMet/pass, corpusFingerprint - byte-for-byte the harness's canonical() + sha256), and the derive REQUIRES it to equal the ledger's signed precision_digest. A cache that lies about its floor fails the recomputation. The real enforce->codegen integration test is the drift guard for the replicated canonical/digest. verify: enforced-rules-generation.test 57/0 (rejects a recompute mismatch + a missing recompute); test-enforced-codegen.sh 23/0 (a REWRITTEN cache floor-field -> recompute mismatch -> codegen exit 4; honest cache OK again after restore).
- CAVEAT A (DOCUMENT-ONLY, NOT code-closable): SIDECOACH_ENFORCE_TEST_ROOT is a PRODUCTION-FORBIDDEN env var. Every test-seam gate (the toggle flag env, the build-cmd override, the precision-floor env) assumes it is NOT set in a real run; an agent that sets it ITSELF in production re-opens the seams - the SAME accepted same-uid limit (an agent controlling its own env is an agent acting as the user), NOT fenceable (an env var is agent-settable and the tests legitimately set it). Documented plainly in taste-blocking-toggle.ts + sidecoach-taste-enforce.js + this beat; surfaced to the user; never set in production. This is the fundamental same-uid floor - the last round.
